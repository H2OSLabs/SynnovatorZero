# 1. 评委评审流程

- **角色:** 认证评委 (Judge)
- **前置条件:**
    - 已使用认证评委账户登录。
    - 已被活动组织者邀请加入特定活动的评审团。
    - 活动已进入评审周期 (`review_start` <= now < `review_end`)。

## 1.1 接收任务与执行评审

评审工作由系统通知驱动，评委无需主动寻找任务。

| 步骤 | 用户操作 | 系统行为与数据操作 | 说明 |
|------|----------|--------------------|------|
| 1 | **接收评审任务** | - 系统在评审周期开始时，自动为评委分配作品。<br>- `CREATE notification` (type: review_task, recipient: judge) | 评委会在通知中心收到一条新的评审任务通知，内容包含活动名称和打分链接。 |
| 2 | **进入打分页面** | 用户点击通知中的链接。 | 链接直接将评委导航至一个专属的、集中的打分页面。 |
| 3 | **浏览待审作品** | 在打分页面，评委可以看到一个清晰的待审作品列表。 | `READ submission` (filtered by judge_id) |
| 4 | **对单个作品打分** | - 点击某个作品，查看其完整内容。<br>- 根据组织者预设的评分维度，逐项填写分数和评语。 | - `READ submission` (full content)<br>- UI 上展示 `Rule.review_criteria` 定义的评分表单。 |
| 5 | **提交单个作品分数** | 完成打分后，点击“提交此份评审”。 | `CREATE review` (submission_id, judge_id, scores, comments, status: pending_approval) |
| 6 | **完成所有任务** | 重复步骤 4-5，直到所有分配的作品都完成评审。 | 评委的打分页面会显示进度，例如 "已完成 5/10"。 |

- **结果:** 评委完成了所有分配的评审任务。所有分数已提交至系统，等待管理员的最终审核。
