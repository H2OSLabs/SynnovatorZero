# 2. 评审管理 (Admin)

- **角色:** 管理员 (Admin)
- **前置条件:** 已使用管理员账户登录。

## 2.1 评委资格认证

管理员负责维护平台内认证评委的池子，确保评审的专业性和公正性。

| 步骤 | 用户操作 | 数据操作 | 说明 |
|------|----------|----------|------|
| 1 | **审核评委申请** | 管理员在后台的“用户管理” -> “评委申请”列表中，查看申请人信息。 | `READ user` (where role_application = 'judge') |
| 2 | **评估资质** | 点击查看申请人的个人主页、历史贡献等信息，以评估其专业能力。 | `READ user` (full profile) |
| 3 | **授权或拒绝** | - **通过**: 将用户的角色更新为“评委”。<br>- **拒绝**: 驳回申请，可选择性填写理由。 | `UPDATE user` (set role = 'judge') 或 `UPDATE user` (set role_application = 'rejected') |

- **结果:** 平台拥有了一批经过认证的、可供活动组织者选择的评委。

## 2.2 评审结果审核与发布

在人工评审活动中，管理员是结果发布的最终把关人。

| 步骤 | 用户操作 | 数据操作 | 说明 |
|------|----------|----------|------|
| 1 | **监控评审进度** | 在活动管理后台的“评审”标签页，查看当前活动的整体评审进度，例如“已完成 80%”。 | `READ review` (aggregated by event_id) |
| 2 | **审查分数详情** | 所有评委提交完毕后，管理员可以查看每个作品收到的所有打分详情，包括各维度分数和评语。 | `READ review` (grouped by submission_id) |
| 3 | **处理异常分数** | (可选) 如果发现某个评委的打分有明显偏离，管理员有权标记或提请复议，但通常不直接修改分数。 | - |
| 4 | **最终审批** | 确认所有分数无误后，管理员点击“批准并计算最终结果”按钮。 | `UPDATE event` (set status = 'calculating_results') |
| 5 | **发布结果** | 系统根据管理员的审批，自动计算每个作品的最终得分（如加权平均分），并更新活动排名。管理员点击“发布结果”。 | `UPDATE event` (set status = 'results_published') + `CREATE notification` (to all participants) |

- **结果:** 活动的最终排名和分数被公布，所有参与者都会收到通知。
